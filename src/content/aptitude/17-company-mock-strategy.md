# Company mock test strategy

Company preparation fails when mocks are treated like score screenshots. A mock
is a diagnostic machine. Its job is to expose which section, topic, and mistake
type will eliminate you.

## Mock cycle

Use every mock in this loop:

```text
simulate -> score -> tag mistakes -> repair -> retake smaller section -> retake full mock
```

Do not immediately take another full mock after a bad score. Repair first.

## Score sheet

After every mock, record:

| Field | Example |
|---|---|
| Company | TCS / Infosys / Accenture |
| Mock ID | tcs-nqt-cognitive |
| Section | Numerical |
| Score | 11/20 |
| Time issue | yes/no |
| Mistake type | formula, arithmetic, wrong pattern, reading, panic |
| Repair action | redo percentages + DI |
| Retest date | tomorrow |

## Mistake taxonomy

| Mistake | Meaning | Repair |
|---|---|---|
| Formula | Did not know the rule | Read formula lesson, do 10 examples |
| Classification | Picked wrong topic/pattern | Write trigger words |
| Arithmetic | Method right, calculation wrong | Estimate before calculating |
| Reading | Misread condition | Underline givens and unknown |
| Time | Too slow | Add skip rule and section timer |
| Edge case | Code passed sample only | Add hidden-case checklist |
| Technical concept | Confused definitions | Write definition + example |
| Communication | Could not speak clearly | Record 2-minute answer |

## Section retake rule

If a section is below gate, do not retake full mocks.

```text
Below 60%: learn concept again.
60-75%: section drills.
75-85%: timed section mocks.
85%+: full mock integration.
```

## Company-specific mock order

### TCS

1. `tcs-nqt-cognitive`
2. repair weakest cognitive section
3. `tcs-nqt-it-full`
4. two coding problems under timer
5. retake cognitive after 48 hours

TCS risk is time, especially numerical and section switching.

### Infosys

1. `infosys-pseudocode-sprint`
2. repair tracing mistakes
3. `infosys-irt`
4. puzzle/verbal repair
5. role-specific coding if DSE/SP

Infosys risk is logic and pseudocode precision.

### Accenture

1. `accenture-cognitive-technical`
2. repair technical breadth
3. `accenture-coding`
4. communication drill
5. `accenture-full-flow`

Accenture risk is ignoring cognitive/communication while overtraining DSA.

## 7-day company mock sprint

| Day | Work |
|---:|---|
| 1 | Company playbook + diagnostic mini mock |
| 2 | Repair lowest cognitive section |
| 3 | Technical/pseudocode/coding drill |
| 4 | Timed section mock |
| 5 | Full mock |
| 6 | Repair only repeated mistakes |
| 7 | Final mock + interview explanation practice |

## 30-day company mock sprint

Use four weekly cycles:

```text
Week 1: foundation and diagnostic
Week 2: weak-section repair
Week 3: full mocks and coding pressure
Week 4: final polish, communication, interview answers
```

By week 4, do not learn random new topics unless a repeated mistake demands it.

## Readiness gates

Before applying, aim for:

```text
section scores >= 75%
no section below 65%
coding passes hidden edge checklist
pseudocode trace accuracy >= 80%
communication answer clear for 2 minutes
mistake log has no repeated top mistake for 3 mocks
```

## Final rule

The candidate who wins is not the one who solved the most random questions. The
candidate who wins is the one who removes repeated failure modes fastest.
