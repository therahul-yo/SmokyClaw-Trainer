# Dynamic Programming — 2D

1D DP tracked one moving index. 2D DP tracks **two** — usually positions in two
sequences, or a row/column in a grid. The recurrence now reads from up to three
neighbours (`dp[i-1][j]`, `dp[i][j-1]`, `dp[i-1][j-1]`), and the whole skill is
naming what `dp[i][j]` *means* before you write a single loop.

## The thinking pattern

Same five steps as 1D — the state just grows by one dimension:

1. **State.** Two variables: `i`, `j`. For two strings, indices into each. For a grid, row/col.
2. **Definition.** Write `dp[i][j]` as an English contract: *"the answer considering the first `i` of A and first `j` of B."*
3. **Recurrence.** Which neighbours feed `dp[i][j]`? Almost always the cell above, left, and/or diagonal.
4. **Base case.** The first row and first column — often "empty input," which is `0`, `1`, or `j`/`i`.
5. **Answer.** Usually `dp[m][n]` (the bottom-right corner).

A `(m+1) × (n+1)` table with an extra row/column of base cases is the cleanest
convention — it removes most off-by-one pain.

## Unique paths — the grid warm-up

A robot at the top-left of an `m × n` grid moves only right or down. How many
paths to the bottom-right?

```python
def unique_paths(m, n):
    dp = [[1] * n for _ in range(m)]      # first row & col are all 1
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i-1][j] + dp[i][j-1]
    return dp[m-1][n-1]
```

- Definition: `dp[i][j]` = number of paths to reach cell `(i, j)`.
- Recurrence: you arrive from above or from the left, so sum those two.
- Base: the top row and left column each have exactly one path (straight line).

## Longest Common Subsequence — the two-string template

LCS is *the* pattern to memorize; edit distance, shortest common supersequence,
and diff all reuse its shape.

```python
def lcs(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i-1] == b[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1     # match: take the diagonal + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])  # skip one char
    return dp[m][n]
```

- Definition: `dp[i][j]` = LCS length of `a[:i]` and `b[:j]`.
- **Matching characters → diagonal + 1.** Mismatched → drop a character from one
  string and take the better result. This match/diagonal-vs-mismatch/max split is
  the heart of nearly every string DP.

## Edit distance — same skeleton, three choices

Minimum insert/delete/replace operations to turn `a` into `b`:

```python
def edit_distance(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): dp[i][0] = i        # delete all of a[:i]
    for j in range(n + 1): dp[0][j] = j        # insert all of b[:j]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i-1] == b[j-1]:
                dp[i][j] = dp[i-1][j-1]
            else:
                dp[i][j] = 1 + min(dp[i-1][j],      # delete
                                   dp[i][j-1],      # insert
                                   dp[i-1][j-1])    # replace
    return dp[m][n]
```

The base cases here actually carry information (cost `i`/`j`), unlike LCS where
they're zero — always ask what an empty prefix *costs*.

## 0/1 knapsack — capacity as the second axis

```python
def knapsack(weights, values, cap):
    n = len(weights)
    dp = [[0] * (cap + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for c in range(cap + 1):
            dp[i][c] = dp[i-1][c]                       # skip item i
            if weights[i-1] <= c:
                dp[i][c] = max(dp[i][c],
                               dp[i-1][c - weights[i-1]] + values[i-1])  # take it
    return dp[n][cap]
```

Here the second index isn't a string position — it's **remaining capacity**.
Recognizing that "the second dimension is a resource budget" unlocks subset-sum,
partition, and coin-combination problems too.

## Space optimization — collapse to a rolling row

If `dp[i][j]` only reads row `i-1`, you need just two rows — or one, if you
iterate `j` carefully:

```python
def lcs_1d(a, b):
    prev = [0] * (len(b) + 1)
    for ch in a:
        cur = [0] * (len(b) + 1)
        for j in range(1, len(b) + 1):
            cur[j] = prev[j-1] + 1 if ch == b[j-1] else max(prev[j], cur[j-1])
        prev = cur
    return prev[-1]
```

Knapsack collapses to a single array if you iterate capacity **downward**
(right-to-left) so each item is used at most once. Get that direction wrong and
0/1 knapsack silently becomes unbounded knapsack.

## Recognizing a 2D-DP problem

- Two sequences compared (subsequence, alignment, matching, interleaving).
- A grid with movement constraints (paths, min-cost path, obstacles).
- "Choose a subset under a budget/capacity" — the second axis is the budget.
- An interval `dp[i][j]` over a range `[i..j]` (matrix-chain, burst balloons, palindrome partition) — a different but related 2D shape.

## 2D vs 1D — when the extra axis is real

| Signal | Dimensions |
|---|---|
| State is a single position/amount | 1D |
| Comparing two strings / sequences | 2D (i, j) |
| Moving on a grid | 2D (row, col) |
| Subset choice **and** a capacity limit | 2D (item, capacity) |
| Answer depends on a sub-range `[i..j]` | 2D interval DP |

## Common bugs

- **`(m+1)×(n+1)` vs `m×n` confusion.** Decide whether index `i` means "first `i`
  chars" (1-based, needs `a[i-1]`) or "char at `i`" (0-based) — and stay consistent.
- **Forgetting base rows/columns carry cost.** Edit distance's first row is `j`,
  not `0`. A zeroed base case here gives wrong answers silently.
- **Wrong knapsack iteration direction** when space-optimizing — downward for 0/1,
  upward for unbounded.
- **Reading a neighbour you haven't computed yet.** Diagonal `dp[i-1][j-1]` must be
  filled before `dp[i][j]`; the natural row-major order handles this, but a
  rolling-array rewrite can clobber it — save the diagonal in a temp first.
